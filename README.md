# Fuzzy Flight Lab

GFT（ファジーの階層結合）と小型ニューラルネットワークを切り替え、GAで育てるブラウザ教育用AIデモ。

公開: https://kojira.github.io/fuzzy-flight-lab/

## 遊び方

1. 判断方式でGFT / NNを選択。「学習スタート」で固定配置を学習。「学習ストップ」で停止、「＋1世代」で一段ずつ進めます。
2. 障害物をドラッグ、またはタップして選択→移動先をタップ。同じ個体を変更した評価配置で試せます。選択後は矢印キーでも移動可能です。
3. seedを入力して「この方式を初期化」すると、現在方式の初期個体・世代・履歴と共通の評価配置をリセット。別方式の学習は保持。切替時は学習を停止し、方式ごとのseed・初期最良・現在最良・履歴・乱数の進行を復元します。同じ方式・seed・世代なら同じ結果です。

課題は固定270step以内の到達（旧版は580step）。直線距離770・最高巡航速度3.5に対し、旋回・減速も考慮した時間制約です。物理・GFTの遺伝子範囲・一様ランダム初期集団は旧版と同じ。NNは別の45遺伝子を使います。世代により制限を変えません。

Canvasは1ケースのリプレイ。紫の破線＝初期集団の最良、水色＝現在表示世代の最良。同じ配置・同じ選択初期向きで重ねて比較します。チェックで初期軌跡を隠せます。ライブのGFT所属度 / NN入力・隠れ層・活性化出力と制御出力はその飛行個体から計算されます。学習中も飛行を最後まで再生してから最新世代へ切り替えるため、画面の「世代」と集計の最新世代が異なる場合があります。

学習配置と編集した評価配置を分離しています。両方の成績は同じ3つの初期向きで実際にシミュレーションした到達数・平均得点です。グラフは学習配置での最良個体の実測平均得点。上昇するようなダミー値は使いません。初期集団最良と現在最良の到達数・平均得点・衝突・時間切れを、学習配置／変更評価配置のそれぞれで並べます。失敗を衝突と偽らず時間切れと表示。seedによって初期全到達や停滞もあり得ます。

## 中の仕組み

距離センサー → 所属度 → 回避モジュールとゴール誘導モジュール → 危険度に応じた調停 → 旋回・速度、という小さなファジーモジュールの階層結合です。通常の二分決定木ではありません。「近い」所属度は `clamp(1 - 距離 / 閾値, 0, 1)`。左右の所属度差などから回避を計算し、調停モジュールが連続混合します。

7つの実数遺伝子（距離閾値・誘導強度・回避強度・回避優先度・センサー角度・左右バイアス・巡航速度）を24個体・3ケースで評価。3個体トーナメント選択、遺伝子単位のブレンド交叉、23%の確率で範囲幅の±22%の突然変異、上位2個体のエリート保存を行います。各世代の計算は同期処理ですが、世代間で描画と操作に制御を返します。

得点 = 最終位置の接近度×180 ＋ 到達420 − 衝突100 − step×0.06。接近度は `1 - min(1, ゴール距離/770)`、時間切れは270step。進化の目的はこの小さな採点関数だけです。

### 小型ニューラルネットワーク

NNは左前/前/右前の距離÷300とゴール方向誤差÷πの4入力 → 隠れ6ユニット（tanh） → 2出力（旋回tanh、速度sigmoid）。各ユニットが実際に重み付き和＋バイアスを計算します。速度は0.48〜3.5 px/stepへ変換。44個の重み・バイアス（−2〜2）とセンサー角度（GFTと同範囲）の計45遺伝子を、一様ランダムから探索します。NNも24個体・3ケース・トーナメント選択・ブレンド交叉・上位2個体保存。NNの突然変異率は10%、幅は範囲の±10%です。誤差逆伝播や深層強化学習ではありません。

生センサーの情報（距離3値とゴール方向）、コース、初期向き3ケース、270step、衝突・採点を共通化。方式ごとにセンサー角度も探索します。GFTには人の回避構造の知識があり、NNには探索次元の多さがあるため、同世代＝同計算量でも公平な性能ランキングでもありません。NNが万能なことを示すデモではありません。

## 注意

所属度は確率ではありません。最適解や未知配置への汎化は保証しません。変更配置では衝突・時間切れが起きます。2016年の[ALPHA紹介記事](https://magazine.uc.edu/editors_picks/recent_features/alpha.html)に着想を得た教育用簡略モデルで、論文・ALPHA・航空機制御の再現ではありません。

## ローカル実行・テスト

実行時依存なし（HTML / CSS / ES Modules）。外部フォント・解析・API呼び出しなし。

```sh
python3 -m http.server 8000
# http://localhost:8000 を開く
node --test tests/core.test.mjs
```

`tests/browser.mjs` は、検証環境にインストール済みのPlaywrightとChromeを使う開発用ブラウザテストです（ランタイム依存ではありません）。`PLAYWRIGHT_MODULE` で既存Playwrightのimport先を指定できます。実行すると一時的なHTTPサーバーを起動し、終了時に閉じます。スクリーンショットは `artifacts/`。

複数seedの実測: `node tests/measure-nn.mjs`（同じ固定20seed × 両方式 × 80世代、`artifacts/nn-multi-seed.json`）。GFTは35/80世代とも20/20seedが3/3、NNは35世代15/20、80世代16/20seedが3/3（80世代の全ケース到達数は50/60）。両方式とも初期3/3のseedは0/20。デフォルトNNは0/3・31.25点→80世代3/3・580.43点。NNの `flight-2` / `flight-3` / `flight-6` は得点が伸びても80世代0/3、`flight-9` は2/3のまま。全seedで得点は改善しましたが、到達しない例も隠していません。任意seed・未知配置への成功保証や一般的な性能優劣ではありません。固定学習配置3/3でも変更配置0/3になる失敗をChromeで確認しています。

検証: `node --test tests/core.test.mjs`（15テスト）、`tests/browser.mjs`（既存GFT回帰）、`tests/browser-nn.mjs`（両方式Chrome）。`tests/negative.mjs` は重み計算・方式状態・NN物理呼び出し・LIVE値・リセットを一時的に壊し、対応するテストがfailすることを確認して必ず復元します。開発用Playwrightは `PLAYWRIGHT_MODULE` で指定し、実行時依存には加えません。

同じJSエンジン・seed・世代では再現。NodeとChromeの三角関数には微小な浮動小数点差があるため、異なるエンジン間のビット一致は保証しません。
